# hub-plugin-projects-status

<img src="icon.png" width="256" alt="Статус проектов">

Плагин страницы Agents Hub «Статус проектов»: все проекты из `hub projects` - что ждёт ответа владельца, что идёт
(этап, бэклог направления), что готово, что без направления. Главная - «Доска» (переключатель «Доска | Список», выбор помнит
браузер): приложения по этапам, колонки Кандидат → Разработка → К релизу → В сторе, у «Разработки» - лимит 1 (больше -
метка горит); «Пауза», «Готово» и «Без этапа» свёрнуты под доской. На доске только приложения: тип проекта в памяти
(`app`, `site`, `legal`, `invite`, `sandbox`, `research`, `other`; без отметки - приложение, так кандидаты ресёрча с
этапом «Кандидат» попадают сами), правится в карточке («Тип») или `pmem.py set <проект> --kind …`. В «В сторе» - цифры
магазина, которые записала сессия: `pmem.py set <проект> --store "<загрузки и выручка>"`. У проекта может быть ссылка на его
файл в Figma (одна, только `https://www.figma.com/…` или `https://figma.com/…`): кнопка «Figma» в шапке карточки и значок на
доске и в «Списке», открывается в новой вкладке; правится в карточке («Править» → «Figma», пусто - убрать) или
`pmem.py set <проект> --figma "<ссылка>"` (`--figma ""` - убрать). Карточка проекта - его память: этап, цель, «что дальше»,
ключевые решения и история правок с автором. Вкладка «Задачи» - доска проекта: новая задача (тип, приоритет,
исполнитель - сессия или сам владелец, срок), статус меняется перетаскиванием. Клик по карточке открывает окно задачи,
как в Jira: название, описание, статус, исполнитель, приоритет, тип и срок правятся на месте (⌘↩ - сохранить), там же
«Копировать» (номер, название и описание) и «Удалить». Меню «⋯» на карточке: открыть, скопировать текст или номер,
сменить статус, удалить. Удалённая задача уходит в архив бэклога (`archive/tasks`), файл и номер остаются. Задачи - файлы Backlog.md: бэклог
одного из живых направлений проекта или свой бэклог `<state>/projects-memory/<проект>/backlog` (поле «Куда»).

У проекта может быть несколько направлений: все, чьё репо - папка проекта (или внутри неё), и привязанные вручную
(направление с другим репо, например Android-версия: «Привязать направление» в карточке или `pmem.py set <проект> --link
<направление>`). Поле «Написать проекту» в карточке и «Написать по проектам» на главной - как чат Хаба: сообщение уходит
Хабу с контекстом проекта (папка, направления и кто их ведёт), и он решает, кому его отдать - ведущему направления,
агенту или задачей.
Вопрос-карточку сессии в «Ждёт вас» можно ответить на месте: вариантом, своими словами или «Разрешить»/«Запретить».
«Что изменилось» вверху - правки памяти и закрытые задачи с прошлого «Прочитал», у проектов - отметки «новое» и
«изменилось» (без модели; прочтение помнит браузер). Адреса, ключи Jira и MR/PR в тексте - ссылки; в карточке видно, кто
сейчас работает над проектом.
Блок «Репо» в карточке - живое состояние git папки проекта (и репо привязанных направлений): ветка, последний коммит,
сколько коммитов не запушено и файлов не закоммичено, открытые PR (GitHub, через `gh`) и MR (GitLab, через `glab`) -
с входом этих программ на Mac, раз в 10 минут; git - раз в минуту. Кнопка «Открыть в Finder» (в Windows - Проводник) у блока «Репо» и в «Ссылках» открывает папку проекта или репо на этом компьютере: процесс плагина открывает только папки проектов и их репо. Проект на этапе «Разработка» или «К релизу» без
коммитов 7 дней, над которым никто не работает и который не ждёт вас, помечен «застыл».
Раздел и фильтр «Не запушено» - проекты, где у локальных веток есть коммиты, которых нет ни в одной удалённой ветке
(по каждой ветке; ветка, удалённая на сервере после слияния, не в счёт), и репо без удалённого.
Задачи без проекта (кнопка «Новая задача», проект «Без проекта») - в общем бэклоге
`<state>/projects-memory/_general/backlog`. Задачи владельца стоят в «Ждёт вас».

- `main.py` - процесс плагина: сворачивает правки памяти из канала плагина (`hub post projects-status '<json>'`) в
  `<state>/projects-memory/memory.json` и `<проект>.md`, отдаёт данные странице на порту «порт страницы + 12».
- `pmem.py` - для сессий: `pmem.py show [<проект>]`, `pmem.py set <проект> --stage … --note … --goal … --add … --done …
  --kind … --store … --figma …`,
  `pmem.py set <проект> --link|--unlink <направление>`, `pmem.py task list|new|status <проект> … [--direction <направление>]`
  (проект `-` - без проекта).
- `repo.py` - состояние репо проектов для блока «Репо» (кэш в процессе плагина).
- `web/` - вид страницы (API плагинов `^1.7`).

Подключение - строка в `extensions` настроек хаба:

```json
"projects-status": {"path": "<папка плагина>", "run": ["python3", "main.py"], "web": "web/main.js", "hub": "^1.7"}
```

Чтобы память заполнялась сама, нужно правило для всех сессий - строка в `rules` настроек хаба (`<папка плагина>` - его
`path` в `extensions`):

```text
Память проекта (вид «Статус проектов» у владельца): этап, цель, «что дальше» каждого проекта из hub projects. Работаешь в папке проекта - в начале прочитай: python3 <папка плагина>/pmem.py show. Перед итогом задачи, после которой изменилось, где проект (сделан пункт «что дальше», появился крупный следующий шаг, вышла версия), - запиши: pmem.py set <проект> --done "<начало пункта>" / --add "<шаг>" / --stage <этап> --note "<что сейчас>". Мелкая правка, которая план не двигает, - без записи. Этапы: Кандидат, Разработка, К релизу, В сторе, Пауза, Готово; «В сторе» и «Готово» - по факту или слову владельца, цель - только со слов владельца.
```

На эвале (сделан пункт, опечатка, вышла версия) с этим правилом сессии записали верно 6 из 6, со скиллом - 1 из 12.

Тесты: `PYTHONPATH=<код хаба> python3 -m unittest discover -s tests`.
